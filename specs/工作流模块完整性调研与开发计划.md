## 4. 建议的开发顺序（最小闭环优先）

```
阶段一（必做，1~1.5 人日）：P0-1 Agent 绑定工作流 UI → P0-2 对话联调验证
阶段二（体验补全，1~2 人日）：P1-1 工作流编辑 → P1-2/P1-3 执行记录查询与查看页
阶段三（质量加固，1.5~2 人日）：P2-1 状态操作 → P2-2 测试 → P2-3 静默失败修复
```

阶段一完成后即可验收：新建/编辑 Agent 时选择工作流 → 对话页显示"工作流模式"标签 → 发送售前/售后/技术支持问题分别走不同路径回答。

## 5. 附：执行时需遵守的项目约定

- 错误码走 `ErrorCode` 枚举（工作流段 6000 起，新增接口错误不可硬编码）。
- 前端走 `Result<T>`/`PageResult<T>` 约定，接口风格 `/api/v1/{资源}`。
- 工作流执行必须保持同步、复用 llmExecutor，禁止 `new Thread()`。
- 改完跑 `mvn clean install -DskipTests` + mock profile 启动验证；前端 `npm run dev` 联调。
- 完成后用 docs-auto-sync 技能同步 `docs/api-list.md` 等资产。
